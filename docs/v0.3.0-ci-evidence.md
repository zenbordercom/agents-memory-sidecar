## Node Compatibility

The CI matrix passed on Node.js 22 and 24. Both jobs ran install, typecheck,
build, documentation checks, unit tests, fake-store smoke, HTTP smoke, HTTP
bridge smoke, and fail-closed security smoke. The Node 24 job also passed the
critical-module coverage threshold.

`docs:check` validates Markdown links, documented environment variables, and
the syntax of every fenced `bash`, `sh`, or `shell` command block using
`bash -n`. The Compose job separately parses and executes the repository's
`compose.yaml` through the clean-start and restart-persistence smoke.

Coverage is intentionally evaluated on Node 24 only. Node 22's V8 coverage
mapping with `tsx` undercounts TypeScript lines despite passing the same tests;
the Node 22 compatibility gate remains functional validation rather than a
duplicate instrumentation gate.

## PostgreSQL And Search

The CI PostgreSQL job used `pgvector/pgvector:pg16` and passed:

```text
npm run db:migrate
npm run postgres:smoke
npm run search:benchmark
```

`postgres:smoke` completed migration and lifecycle checks. The benchmark ran
against PostgreSQL with fixture model `fixture-3d-v1` and dimension `3`; it
reported keyword, semantic, and hybrid measurements with latency, result count,
`recall_at_5`, reciprocal rank, actual mode, model, and fallback fields.
Semantic and hybrid fixture queries each reported `recall_at_5: 1`. The
embedding-not-configured scenario reported the deliberate hybrid-to-keyword
fallback.

## Docker Compose

The CI Compose job built the production image and ran `npm run compose:smoke`.
It created an isolated PostgreSQL volume, waited for both health checks, wrote
a token-authenticated memory, restarted the sidecar, verified that the memory
persisted, and removed the containers, volume, and network. The job reported
`compose smoke ok`.

The smoke also runs the documented CLI-over-HTTP durable path: it writes with
`memory_add`, restarts the sidecar, then verifies the same item through
`memory_search` and `memory_get`. This supplies the core write/search/read
evidence from the 30-minute durable deployment transcript in a fresh CI
checkout.

The first CI Compose run found that the Docker build invoked the package's
`prepare` script before `tsconfig.json` and source files were copied. The
Dockerfile now uses `npm ci --ignore-scripts` in the dependency layer and
builds only after copying the full source tree; the following Compose run
passed.

Docker remains unavailable on the authoring host, but this runner evidence
covers the clean-start and restart-persistence behavior defined in the
[v0.3.0 construction plan](v0.3.0-construction-plan.md).

## GitHub Security Settings

Private vulnerability reporting is enabled for the public repository. The npm
environment has a custom deployment policy limited to `v*` release tags.
The v0.3.1 workflow successfully published through npm Trusted Publishing with
GitHub Actions OIDC and provenance enabled. Its later registry metadata check
received a transient 404, so the workflow concluded as failed after publication;
the public npm package, provenance attestation, integrity metadata, and GitHub
Release assets were subsequently verified and reconciled. No long-lived npm
publication token was used by the workflow.
